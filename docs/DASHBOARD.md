# Витрина: экраны, карточки, поля выпуска, плашки, тема

Витрина https://tzi-850-t.pages.dev — шесть экранов на одном выпуске `/api/model` (контракт
`t-v1`, поля — `docs/PAYLOAD.md`, ниже «П§N»). Методика чисел — `docs/MODEL.md` («М§N»).
Источник правды — `web/app.js` (экраны — `SCREENS`, карточки — функции `…Card`); правила
держат тесты витрины `tests/test_web_*.py` и Node-проверки `tests/web/web_app_check.mjs`
(витрина с заглушкой DOM `tests/web/dom_stub.mjs`), `tests/web/web_release_text.mjs` (текст
экранов без служебных строк) и `tests/web/web_functions_check.mjs` (дверь данных) на фикстуре
`tests/fixtures/payload-sample.json`; контракт выпуска — тесты ядра `tests/test_core2_*.py`
(`model/payload.py::validate`). Файлы и владение — `docs/INTERFACES.md`.

Код витрины — общий каркас семейства: дизайн-система, ядро отрисовки и экраны без литералов
эмитента; имя, тикер, подписи нормативов, базиса и делителя — из выпуска. Всё, чем эта панель
отличается, — **новые карточки из существующих компонентов и слова, которые выбирают данные**:
карточка рисуется только при наличии своего узла выпуска, слово общей формы («обеих категорий»,
«РСБУ банка», «купон бессрочных инструментов») печатается только там, где данные его оправдывают.
Выпуск без узлов панели остаётся годным и даёт общую форму экранов.

## 1. Размеры

* **Выпуск** — ≤ 500 000 байт компактного JSON (`meta.bytes`), ориентиры по блокам — П§0.5.

  | **итого** | **< 329 000** | 307 113 |

  них — расширения карточек каркаса по узлам. Разницу дают сжатие комментариев файла, вынос
  повторов в помощники и отступ строк кода табуляцией (один знак на уровень; ширину показа в

  атрибутов — `sx`, `dx`, `lx`, `pa`; подпись ячейки `hint`, `strong`, ряд плиток `kpis`,
  отступ `spaced`, узел с классом и отступом сверху `mt`, `smallNote`; раздел без заголовка —
  `sec`; карточка без своего обязательного блока — `none`; формат с постоянным числом знаков —

  день на оси времени — `dayMs`; узел передачи ставки — `trans`; цвета рядов и имя атрибута
  толщины линии — константы (`MODEL`, `MARKET`, `THIRD`, `INK`, `NEG`, `INK2`, `GREY`, `SURF`,
  `SW`), объявленные один раз. Размеры функций карточек панели, КБ: уровни «на чём стоит
  заголовок» с окном фактов и путём модальной клетки — 4,7; «Рост, на который хватает
  капитала» — 3,1; квартальные DPS — 3,1; пределы и срок — 2,9; мост трёх прибылей — 2,4; путь

  цена правил и развилок — 0,8. Стили новых карточек — существующие классы. Потолков у разделов `app.js` нет — считается файл; текущий
  запас показывает тест веса. Когда запас `app.js` падает ниже 2 КБ, сначала
  снимается повтор, потом просится потолок.

## 2. Правила витрины

* **Числа — только из выпуска**, формул модели во фронте нет. Единственный пересчёт — ползунок
  λ «рыночные ставки как есть ↔ свой макро-взгляд» (П§0.1): центр прогона = низ + λ·(верх −
  низ), квантиль тип 7, печать к `fair_value.headline.print_step` половиной вверх
  (`roundHalfUp` — так печатает ядро, П§0.3). Всё прочее при λ ≠ книги — строки
  `fair_value.headline.by_lambda` и `fair_value.bank_first_line.by_lambda` (`atLambda`). Прочие
  экраны показывают λ книги. Тест `test_the_front_computes_nothing_but_the_books_lambda_rule`.
  Доля прироста кредитных книг (`capital.growth`) — выход ядра: печатается как есть, ползунка у
  неё нет.
* **Арифметика отображения** — только форматирование, доли → проценты, концы «значение ±
  ошибка», минимум–максимум, счётчики, дни до даты от `meta.valuation_date`, возраст выпуска по
  часам зрителя. Потенциал к цене, доходности, P/B, запас норматива, суммы DPS по годам, доля
  урезанного роста — поля выпуска: витрина их не складывает и не вычитает.
* **Карточка рисуется по узлу.** У карточки панели есть свой необязательный узел выпуска (§3,
  графа «Условие»). Узла нет — карточки нет: ни заглушки, ни слова «нет данных». Обязательного
  блока нет — карточка так и пишет (`missing`). Пустой список, которым общий каркас называет
  отсутствие (месяцы РСБУ, проверка формулы DPS), карточку или строку тоже снимает.
* **Слова общей формы выбирают данные**, а не код панели:

  | «на N млн акций в обращении» | поля `meta.shares.divisor_mln` нет | «на N млн: <подпись делителя>» — число и подпись из выпуска |

  Проверка — `web_app_check.mjs` на двух фикстурах: с узлами панели и без них.
* **Литералов эмитента в `app.js` нет** (тест `test_the_front_carries_no_company_literals` с
  шаблонами имени, тикеров, регномера и хостов эмитента; короткий тикер проверяется строковым
  литералом в кавычках, а не границей слова): имя — `company(d)` (`meta.company.name`), тикеры —
  `tickers(d)` и `ticker(d)` (главный). Подписи миров, режимов, сценариев капитала, слоёв,
  гейтов, флагов и нормативов — `title`/`name` из выпуска, не словари `app.js`. **Нормативы —
  только `capital.titles`** (`n20`, `n11`, `n11_observed`, `n1_0`, `n1_2`); ключ метрики выпуска
  (`n20_0` в условии дивиденда) витрина переводит той же подписью (`metricTitle`). Литерала
  «Н1.x»/«Н20.x» в `app.js` нет (тест `test_ratio_labels_come_from_capital_titles`); нормативы
  банка в месячной таблице названы родовыми словами («достаточность капитала банка: всего,
  базового, основного»). Имя эмитента — только статическим текстом в `index.html` и `404.html`.
* **Термины книги — из словаря выпуска `meta.terms`** (помощник `term`): своих слов для них в
  `app.js` нет, без словаря или ключа печатается родовое слово. `lt_level` — слова
  долгосрочного уровня («ЧПМ после фазы роста», «CoR после фазы роста»; помощник `lt`, родовое —
  «долгосрочный»); `roe_lt` — «ROE после фазы роста» в плитках героя и в языке банка (`roeLt`;
  без ключа — из `lt_level`); `cir` — слово отношения расходов к доходам в заголовках столбцов
  и подзаголовках (`ci`; родовое — «C/I»); `noncore` — строка вне основного бизнеса в дереве ROE
  и в таблице «По годам»: в шапке столбца — термин без уточнения в скобках, целиком — в подсказке
  (`noncoreHead`; родовое — «Вне осн. бизнеса»); `stake` и `profit_short` — что исключено из
  прибыли акционеров и как названа прибыль движка в мосте трёх прибылей. Слов «сквозь цикл» и
  «после фазы роста» и имени пакета в `app.js` нет (тест). Те же термины приходят строками
  выпуска — заголовком банковской строки обратного расчёта, заголовками гейтов и подписью
  `fair_value.bank_first_line.sensitivity_basis`; слово `cir` в заголовке гейта и на экранах —
  одно (общая проверка текста, §7).
* **Маржа после фазы роста — суждением.** У книги с ключом уровня (узел
  `nii.transmission.level`) ключ цели (`nii.transmission.nim_lt_target_mgmt`) и есть суждение:
  стационарная маржа на составе баланса якоря в мире, условиям которого отвечает окно фактов;
  уровень мира-опоры передачи — выведенное число (`level.reference_value`), печатается рядом
  справочно. Оба мира названы именами выпуска. Суждение стоит подзаголовком карточки «На чём
  стоит заголовок» на первом экране и на «Допущениях», плиткой «суждение / выведенный уровень
  мира-опоры» на «Расчёте», словами под именем оси — в строке суждения и в строке обратного
  расчёта (`nimPrinted`; числа суждения — значение книги и решение самой строки, второго числа
  рядом нет), там же — уровни смеси заголовка при нужном рынку значении (`levels_solved`,
  `levelsSolved`). Диапазон оси — диапазон самого суждения, оговорок о ключе нет.
  У книги без ключа уровня ключ цели — уровень мира-опоры, а суждение печатает узел гейта
  (`nii.transmission.nim_stationary`: мир, значение, цель и допуск): тогда рядом с ключом везде
  стоит суждение числом — на книге и при нужном рынку значении (`stationary_book`,
  `stationary_solved`; `nimJudged`), а диапазон оси подписан диапазоном ключа («ключ цели: …»,
  «диапазон — тоже ключа цели», `isNimKey`). У книги с целью печатаемой маржи рядом с ключом
  стоит маржа модальной клетки (`nim_lt_printed`, `printed_book`, `printed_solved`) — теми же
  местами.
* **На чём стоит заголовок — уровни из выпуска.** Уровни, которые печатают клетки и слои, —
  результат, а не суждение: карточка `levelsCard` печатает четыре строки узла `paths.levels`
  (модальная клетка, два слоя и смесь заголовка; подписи — `title` строк) — ЧПМ, CoR, C/I и
  долю кредитов в процентных активах, средние за годы участка; рядом — путь прибыли смеси
  (`paths.annual`) и модальной клетки (`paths.modal_cell`: вес клетки в слое и в смеси, цена
  клетки). **Под таблицей — мерка: окно фактов** (подузел `paths.levels.window`, не строка
  таблицы): наименьший и наибольший квартал окна и среднее по ЧПМ, CoR и C/I, доля кредитов в
  процентных активах в среднем за окно и на дату якоря. Фразу «ЧПМ всех строк выше наибольшего
  квартала окна: состав баланса у них другой — кредитов в процентных активах больше, чем в окне
  и на якоре» включает сравнение чисел выпуска, а не код: она печатается, пока наименьшая ЧПМ
  строк больше наибольшего квартала окна, причина в ней — пока наименьшая доля кредитов строк
  больше доли окна и якоря. Средних и разностей витрина не считает.
* **У мира и слоя — одно имя, из выпуска.** Мир печатается именем `worlds.rows.*.name`, слой —
  `layers.*.title`; своих слов для них в `app.js` нет. Клетка называется тремя именами выпуска —
  мир, режим, сценарий капитала (`cellName`; так же — метки клеток `W/r/s` в сообщениях гейтов,
  флагах и строках сверки, `wordsText`): буквы мира в названии клетки нет. Буква остаётся на
  «Расчёте», где она введена подписью ряда («N — <имя мира>» в легенде кривых и в сетке) и
  служит сокращением в таблицах миров и передачи ставки; в строках выпуска (сообщения гейтов,
  названия осей и строк сверки) мир назван словами источника строки.
  Веса миров в карточке «Миры ставок» подписаны слоями выпуска («Вес: <слой>»); смесь заголовка
  в подзаголовке дерева ROE названа строкой `layers.headline_mix.title` — теми же именами слоёв,
  что карточка слоёв.
* **Базы названы там, где числа стоят рядом.** «Пределы и срок»: обе границы — «капитал без
  премии» и «без опережающего роста» — выпуск считает от точки при значениях книги; в подписи
  каждой — её разность с точкой (`bank_rows[].delta`), в подзаголовке — «обе границы считаны от
  точки, а не от медианы полосы», медианы на этой шкале нет. «Режимы»: ожидание CoR — по ключам
  режимов книги, а не уровень слоя; строка отсылает к карточке уровней на «Оценке». «Путь ROE и
  роста капитала к терминалу»: линии — средние по клеткам под вероятностями точки, знак
  разности линий — не знак прироста стоимости (остаточный доход считается в каждой клетке по её
  ставкам); ROE терминала подписан «на капитале без избытка». «Сверка с контрольной моделью»:
  числа сводки стоят на книге, её цене и дате (`valuation_date`), день счёта — отдельно
  (`as_of`); на экране — выдержка, счёт строк вне допуска — всей сводки (`n_rows`, `n_bad`).
* **Решение по подвыборке так и подписано.** У книги со списком строк, корень которых уточняется
  на полной полосе (`reverse_dcf.refine_rows`), решённая строка вне списка несёт подпись «оценка
  по подвыборке» (`bySample`): на «Оценке» — в строке «в диапазоне книги», на «Что в цене» — под
  плашкой строки и в таблице. Правило — слова `method` выпуска под карточкой.
* **С требованием сравнивается строка, названная выпуском** (`capital.requirement.compare`): у
  второго норматива — с прибылью периода; отчётный печатается справочно, подписи двух строк —
  словами выпуска (`notes`). Отчётный норматив ниже требования — не нарушение правила роста, и
  экран не рисует эту пару так, будто оно есть.
* **Требование — то, с которым сравнивает правило роста.** Правило роста сравнивает норматив с
  требованием с глиссадой, поэтому запас якоря печатается обоими числами выпуска: до требования
  с глиссадой к концу названного квартала (`n20_headroom_glide`, `req20_glide_next`,
  `req20_glide_period`) и до требования года (`n20_headroom`); годовой путь смеси идёт против
  требования с глиссадой (`requirement.years_mix.req20_glide`), требование года — тонкой линией.
* **DPS года — «по политике» и «ожидание».** Главная цифра — DPS политики года
  (`nowcast.year.dps`); когда ожидание по клеткам (`dividends.model[].dps`: с отменой решений в
  кризисе) ниже, оно стоит второй строкой (`dpsExpected`). Доходность «четыре ближайших
  квартала» подписана: без объявления — по политике.
* **Обозначений модели на экране нет:** стоимость капитала, рост терминала, ROE после фазы
  роста (термин книги), «после наблюдений кварталов» — словами; имён `k_T`, `g_T`, `ROE'_T` и
  кодов разделов книги в словах самой витрины нет (названия осей и гейтов — слова книги).
* **Сумма дивиденда — с базой.** База суммы — код узла (`dividends.amount_basis`,
  `fair_value.bridge.amount_basis`), слова — подпись выпуска (`amountBasis`): реестр — на все
  размещённые акции, мост — на акции в обращении.
* **Гейты — общим списком, без слов о них в коде.** Заголовок, масса, срок объяснения, коридор,
  сообщение с числами и объяснение приходят из выпуска (`gatesCard`); гейты суждения о марже,
  уровней, стоимости средств и знака (`nim_stationary`, `window_backtest`, `funds_cost_to_key`,
  `nim_lt`, `volume_sign`, `stress_sign`) печатаются так же, как прочие; базу массы гейта знака
  стресса называет его сообщение. Объяснение сработавшего гейта повторяется в карточке его темы
  (`gateNote`) — по имени гейта, с заголовком выпуска.
* **Базис подписан** у каждого отчётного числа словарём `BASIS` (все коды П§0.2: «МСФО группы»,
  «РСБУ банка», «упр.», «движок», «норматив ЦБ», «прогноз сектора», «рынок»). **У каждого ROE и
  P/E — ещё и подпись прибыли**: `meta.basis_labels.roe` у ROE выпуска, `meta.basis_labels.profit`
  у P/E и прибыли, `history.ltm.roe_issuer.label` у ROE эмитента; делитель — `meta.basis_labels.divisor`
  и `meta.shares.divisor_label`. Подпись стоит в подписи плитки или в подвале карточки (`foot`),
  не в подсказке: два ROE рядом без подписи читаются как ошибка. Упр. ЧПМ, CoR и C/I — поля
  `*_mgmt` выпуска, пути CoR режимов в базисе движка — `cor_engine`; мост во фронте не применяется.
* **Названия эталонов** — из выпуска: `nowcast.retro.titles`, затем `next_report.benchmarks[].name`
  и `nowcast.quarter.by_target.*.benchmarks[].name` (`benchNames`); ключ эталона на экран не
  попадает.
* **Доли вклада в полосу** (`contributions[].share`, `judgements.rows[].share`) меньше 1 % —
  «< 1 %» без упорядочивания (погрешность долей ≈ 0,5 п.п. при 2 000 прогонах, М§10; `shareText`).
  Ось вне полосы (`judgements.rows[].in_band = false`) печатается словами «вне полосы» **той же
  мерой, что правило М§10**: на сколько фиксация таких осей сдвигает заголовок и порог гейта
  (`judgements.off_band_shift`, `offBandNote`), а не «вклад < 1 %». Число осей полосы в подписи
  распределения — строки суждений с `in_band` (с осями-словарями), не длина `contributions`.
* **Служебного текста на экране нет** (П§0.2): коды политики дивидендов — `codeText`
  (`CODE_WORDS`: база, делитель, округление, правило нехватки, порядок «рост или дивиденд», вид
  теста истории, периодичность; `true`/`false` — «да»/«нет»); опора книги ЧПД — `refText`;
  метки клеток `W/r/s` и коды периодов в текстах ядра (флаги, сообщения и коридоры гейтов, строки
  сверки) — словами выпуска (`wordsText`, `cellName`, `periodLabel`); единицы `date` и `period` —
  датой и подписью периода (`formatByUnit`). Свободный текст (`ruText`) получает десятичную
  запятую, но версии и ссылки остаются как есть: «книга 1.0», «book-1.0», «М§4.13», «п. 4.1»,
  подписи нормативов (`RU_DECIMAL`; тест гоняет то же выражение в Python). Одна вероятность
  печатается одной функцией (`pBelowText`: от 1 % — целые, меньше — два знака). Строки ядра,
  которые печатаются предложением (сообщение гейта, записка о сроке политики, уравнение
  нау-каста), получают заглавную букву и точку (`sentence(upperFirst(…))` — после `ruText`); после
  многоточия точка не ставится. **Слова для владельца правит источник строки** (книга, факты,
  ядро), а не маска на витрине: кортеж, e-нотацию, метку класса допущения, путь к листу, рабочую
  пометку, дату без года («30.09» читается дробью) витрина не чинит — их ловит общая проверка
  `web_release_text.mjs` (§7). Исключение одно — запись миров: печатается «запись семейства 850,
  версия N» (`worldsRecord` берёт номер из `worlds.source.origin`), имя репозитория записи на
  экран не идёт.
* **Единицы — коды П§0.2**, по величине значения единица не угадывается: строки суждений,
  обратного расчёта и входов — `formatByUnit` (`years` — «4 года», «1,6 года»; `number` — число,
  `pp` — п.п. со знаком); плитки индикаторов — `indicatorValue` (`bn` — млрд ₽, `price` и `rub` —
  ₽, `share` и `pct` — %, `level`, `count` и `number` — число: клиенты в миллионах печатаются
  числом с подписью из заголовка плитки). **Ось-словарь** (вероятности режимов, веса миров)
  печатает диапазон парами концов по ключам — «Кризис 10,0 → 25,0 %» (`rangeText`, `isDict`;
  порядок концов — как у точки на краях; нет конца — «—»; в «торнадо» — ключ с наибольшим ходом).
  **Ось-связка** (`kind: bundle`: несколько чисел книги идут к своим концам одним положением
  оси) печатается как ось одного числа — под именем оси, значением книги и концами первого пути
  (поля `book`, `low`, `high` строки); сколько чисел книги идут вместе, сказано строкой под
  значением. Значение связки в п.п. — уровень, а не сдвиг: ноль печатается «0,0 п.п.», а не
  «без сдвига» (так виден центр премии роста средств клиентов). Словари концов `ends` и имена
  путей на экран не идут.
  Строка обратного расчёта без оси книги (концы диапазона равны) диапазона не печатает
  (`reverseRange`).
* **Слово после числа — по напечатанному числу** (`plural(n, формы, знаков)`): целое — «1 год»,
  «2 года», «5 лет», «21 день»; число с дробной частью — родительный единственного («1,6 года»,
  «2,5 года»). Срок в годах печатает одна функция (`yearsText`): оси суждений, ввод избытка
  капитала, узлы кривой, строка «в цене — N лет». Счётчики «Проверок» согласованы с числом («1
  поднятый флаг», «4 сработавших гейта из 24», «0 нарушенных инвариантов из 14»; знаменатель —
  длина списка выпуска, не константа), число клеток гейта — словом («3 клетки»), сокращения «кл.»
  нет; у гейта, который сравнивает миры целиком (`cells` = 0), счёт клеток не печатается — только
  масса.
* **Сверка с контрольной моделью — в единице строки по виду допуска.** Столбцы уровня: доля
  (`pct`, `share`) — в %, сдвиг доли (`pp`: σ0, спреды, кредитная маржа) — в п.п., как на
  «Расчёте»; деньги — млрд ₽ и ₽. Относительные разность и допуск (`tol_kind: rel`) — в процентах;
  абсолютные — в единице строки (доли и сдвиги — в п.п.) со знаками допуска: знаков — до первой
  значащей цифры допуска и не меньше принятого у единицы (допуск 1·10⁻⁶ доли — «0,0001 п.п.»),
  глубже четырёх — степенью десяти. Разность мельче знаков своего допуска печатается нулём, пока
  строка в допуске; у строки вне допуска разность не прячется.
* **Источник — как пришёл из выпуска.** Историю дивидендов подписывает `dividends.history[].src`
  (`sourcesByYear`): один источник на все решения — строкой, два-три — с годами, больше —
  раскрывающимся списком. Слова пишут факты: решение собрания или рекомендация совета директоров и
  раскрытие эмитента, сверка с брокерским календарём — словами; имён методов и полей API и
  пометок о токене ни в выпуске, ни в витрине нет (общая проверка текста, §7).
* **`null` — не ноль, и на графике тоже.** Линия идёт по непрерывным участкам: через нераскрытое
  значение не проводится, одиночная точка рисуется точкой (`linesChart`). Нулевой столбец несёт
  подпись «0» и цель подсказки, `null` не рисуется; значение меньше единицы подписано с двумя
  знаками (`columnsChart`). Плитка без числа не рисуется — причина печатается строкой; пустой
  интервал — словами («интервал не оценён»). Строка гайденса без числа — «эмитент числа не
  называет», а не «0 %».
* **Легенда собирается из нарисованного:** запись легенды появляется вместе с элементом графика
  (интервал и точка нау-каста, эталоны, гайденс, экс-даты, отметка дробления, смена книги, линии
  рынка, требование с глиссадой), пунктирная и точечная линии — такими же ключами. Проверка —
  `web_app_check.mjs`: каждой записи легенды соответствует элемент той же карточки.
* **Чувствительности языка банка — целыми рублями** (₽ на 1 п.п. ROE, на 0,1 п.п. CoR и ЧПМ, на
  1 п.п. запаса капитала): оценщик срединных прогонов точнее не даёт (М§8.3, §10); местный наклон
  «что даст отчёт» — с одним знаком до 10 ₽.
* **Оценочная дата названа оценкой.** Событие календаря с `estimated: true` или с окном
  (`precision: window`) печатается «≈ дата» и окном «с … по …», в отсчёте — «≈ через N дн.»;
  точной датой оно не называется нигде, в том числе в плашках.
* **Дробление не прячется.** DPS и цены — на акцию после дробления; у решения до дробления
  значение, объявленное собранием, стоит в подсказке (`dps_pre_split`); на графике цены —
  вертикаль события из `meta.shares.corporate_actions` с подписью «цены до этой даты пересчитаны».
  Коэффициент дробления — число выпуска: «1 к 10» в карточке числа акций и в подсказке отметки
  (`splitText`); не число — прочерк.
* **Подпись события на графике не перечёркнута.** Подпись вертикали (экс-дата, дробление, смена
  книги) стоит у своей линии; линия начинается от строки своей подписи и через чужие подписи
  выше не идёт. На узком экране (уже 480 px) подпись короткая — сумма дивиденда, коэффициент
  дробления, число медианы (`short`), слово — в легенде. Подпись горизонтали (медиана модели)
  стоит у правого края, а где её пересекла бы вертикаль события — на свободном от вертикалей
  месте (`linesChart`). Опорная вертикаль «P/B = 1» на гантелях идёт отрезками у строк, мимо
  подписей строк; где она прошла бы через подпись значения, отрезок стоит только под ней
  (`dumbbellChart`).
* **Причины деградации** (`live.degraded`) печатаются словами; адрес в причине — только именем
  сервера (`reasonText`). Дата или период в одном поле (`nowcast.admission.earliest_decision`,
  дата плитки) — по-русски (`dayOrPeriod`: день, «август 2026», «2 кв. 2026»).
* **Единицы периода** — словарь `PERIOD_WORDS`: `meta.period_unit` (`quarter`, модель и МСФО) и
  `meta.input_unit` (`month`, месячный релиз и формы ЦБ). `periodLabel` понимает `2026Q3` →
  «3 кв. 2026», `2026M09` → «сентябрь 2026», год — как есть.
* **Поля — объявленные:** каждое `d.<блок>` — в `REQUIRED_TOP_LEVEL` (тест
  `test_frontend_reads_only_declared_blocks`), поля — из П§2; снятые поля (П§6) витрина не
  читает.
* **Тикеры — списком.** Одна справедливая стоимость на все категории акций (М§8.2); главный тикер
  — `meta.company.main_ticker`: P(ниже рынка), перцентиль и цвет теплокарты — к нему. У эмитента
  одна категория: списки по тикерам несут одну строку, и витрина печатает одну линию рынка и одно
  число, не называя тикер там, где он единственный и уже стоит в брови экрана.
* **Устойчивость:** упал экран или график — «Экран не отрисовался» / «График не отрисовался»
  внутри одной карточки, остальное живо. Графики — свой SVG в настоящих пикселях карточки
  (`chart`), у главных — кнопка «Таблица» (`withTable`) с теми же числами.
* **Диагностики** «что в цене», язык банка и «что даст отчёт» считаны для числа, которое назвал
  выпуск (`target: "median"`): слова экрана («медиана») — по этому полю.
* **«Стоимость капитала» — только ставка** (М§2): V0 в мосте и слоях — «оценка капитала»
  (заголовок строки — из выпуска); у терминала названа база: «PV терминала RI» (остаточный
  доход), «Доля терминала DDM» (дивидендная модель).
* **Дисклеймеров нет** (правило владельца; тест `test_there_are_no_disclaimers_on_the_screen`):
  ни «не рекомендация», ни «не вердикт», ни оговорок о точности ни в подвале, ни в «Как читать»,
  ни в подписях карточек. Ограничение говорится фактом, а не оговоркой: «за шесть кварталов
  прибыль группы отличалась от прибыли банка в 0,85–6,6 раза», «нормативы якоря — оценка до
  выхода формы», «сделка объявлена, в книге её нет».
* **Время — по Москве с пометкой «МСК»** (`mskDay`): момент сборки, время сделки, даты сборки.
  Вероятности режимов — с одним знаком (сумма 100 %), P(ниже рынка) меньше 1 % — с двумя.

## 3. Экраны

Порядок — как в семействе, от ответа к основаниям: Оценка → Что в цене → Расчёт → Ближайший
отчёт → Капитал и дивиденды → Допущения. Адреса — `#overview`, `#market`, `#model`, `#report`,
`#capital`, `#book`; `OLD_HASHES` ведёт `#debt` и `#money` → `#capital`, `#value` → `#overview`,
`#priced` → `#market`; незнакомый или битый хэш открывает «Оценку» и заменяет адрес без новой
записи истории (`screenFromHash`, `syncHash`).

В таблицах: «Условие» — когда карточка или её часть рисуется (пусто — всегда); **панель** — карточка
этой панели, собранная из существующих компонентов (графики `linesChart`, `columnsChart`,
`barTrack`, `waterfall`, `stripChart`, таблица `dataTable`, плитки `kpi`, переключатель `chooser`);
имя функции у такой карточки — целевое.

### 3.1. Оценка (`#overview`)

Шапка экрана (`screenHead`): бровь «Справедливая стоимость акции · <тикеры через точку> ·
<дата оценки>» из `meta.company.tickers` и `meta.valuation_date`.

### 3.5. Капитал и дивиденды (`#capital`)

Узел модели этой панели — «доходность ↔ капитал ↔ рост»: дивиденд платится по политике, а при
нехватке капитала первым уступает рост портфеля. Экран отвечает на три вопроса: хватает ли
капитала под требование с известными ступенями минимума, сколько роста на него хватает и что
получает акционер по кварталам.

Переключатель (`chooser`): «Ожидание» (смесь заголовка) и три сценария капитала — управляет
картами пути нормативов и роста; остальные карточки — смесь заголовка.

## 5. Тема, CSP, палитра, знак, телефон

* **Дизайн-система семейства — байт в байт** («белые карточки на тёплой бумаге», тёмная тема;
  токены `styles.css`): минимальный кегль 12,5 px (брови, подписи графиков), контраст рядов
  ≥ 3 : 1 к карточке в обеих темах. Палитра графиков: синий — модель, оранжевый — рынок,
  бирюзовый — эталоны и третий ряд, красный — отрицательная сторона (разрыв капитала, урезанный
  дивиденд, урезанный рост, минус в водопаде); текст — в цветах текста, не ряда. Цвета графиков —
  только через CSS-переменные: смена темы не требует перерисовки. Новых цветов, шрифтов и
  классов-одиночек карточки панели не вводят.
* **Без фирменного стиля эмитента:** ни логотипа, ни фирменной гаммы; знак — нейтральный глиф
  семейства (`favicon.svg` и знак шапки — один рисунок).
* **Тема:** с 20:00 до 07:00 по часам зрителя страница открывается тёмной (правило владельца для
  всех панелей); днём без ручного выбора — системная; ручной выбор вечером живёт до закрытия
  вкладки (`sessionStorage`), днём — в `localStorage`. Правило — одним инлайн-скриптом в
  `web/index.html` (`window.__theme`: `isNight`, `resolve`, `remember`, окно [20, 7]),
  разрешённым в CSP по sha256. Ключи хранилища — общие для банковских витрин
  (`tzi-theme`, `tzi-theme-tonight`): хранилище у каждого сайта своё (разные адреса), а
  одинаковый скрипт даёт одинаковый хэш CSP у всех панелей семейства.
* **CSP** — одна политика на статике (`web/_headers`) и на функциях (`functions/_middleware.js`,
  `THEME_SCRIPT_HASH`): `default-src 'self'`; скрипты — свои и инлайн-скрипт темы по sha256;
  стили — свои и инлайн; картинки — свои и `data:`; `connect-src 'self'`; `font-src 'self'`;
  `object-src 'none'`; `base-uri 'none'`; `form-action 'none'`; `frame-ancestors 'none'`; плюс
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`. Хэш
  считается по LF-версии скрипта (Python на Windows пишет CRLF); после правки скрипта —
  пересчитать в обоих местах: `test_theme_script_hash_matches_csp` печатает строку на замену,
  равенство политик — `test_csp_is_the_same_in_headers_and_middleware`. Функции — только для
  `/api/*` (`web/_routes.json`); `_middleware.js` держит границу `/api/`: разрешён только
  `model`, прочее — JSON 404.
* **Со сторонних адресов не грузится ничего:** шрифт системный, графики — свой SVG и HTML-полосы
  без библиотек, сборки нет.
* **Телефон (375 px):** широкие таблицы едут внутри карточки с закреплённой первой колонкой,
  число не переносится никогда, свободный текст — второй раскрываемой строкой, мелкого шрифта
  (< 12,5 px) нет. Второстепенные карточки длинных экранов («Ближайший отчёт», «Расчёт», «Капитал
  и дивиденды», на «Допущениях» — сверка с контрольной моделью и отчётная история) на ≤ 720 px
  сворачиваются в «ещё N карточек» — числа при этом не прячутся, раскрываются одним нажатием.
  Примечание в текстовой ячейке таблицы не уже 22 знаков: подпись под значением не рвётся по
  слову на строку. Шапка карточки с переключателем или ссылкой на ≤ 480 px
  переносится: заголовок и подзаголовок — во всю ширину, переключатель — строкой ниже (замер
  `narrowHeads`, §7). Месячная таблица (18 столбцов) на телефоне показывает первые шесть, прочие
  — прокруткой внутри карточки.

## 6. Дверь данных `/api/model`

`functions/api/model.js`: основной источник — GitHub Pages публичного репозитория данных
`temp-zero-inode-850-t-data` (`latest.json` ветки `release` с минутной меткой в запросе,
`cacheTtl` 60 с), запасной — raw той же ветки, третий — последняя годная копия в кэше края.
Адреса и схема — **переменные Pages** в `wrangler.toml` (`[vars]`; INTERFACES §8), в коде функции
нет имени эмитента — дверь общая для панелей семейства и настраивается одним файлом:

| Переменная | Что | Значение (`wrangler.toml`) |
|---|---|---|
| `DATA_SCHEMA` | схема выпуска; ответ источника с другой `schema` — отказ источника | `t-v1` |
| `DATA_PAGES_URL` | основной источник: `latest.json` ветки `release` на GitHub Pages (минутная метка в запросе) | Pages репозитория данных |
| `DATA_RAW_URL` | запасной: raw той же ветки | raw ветки `release` |

Выкладка (§8) везёт их из `wrangler.toml`; в панели Cloudflare их не правят. Нет переменной (или
адрес не `https://`) — 503 `upstream unavailable` без подзапросов. Подзапрос ограничен 8 с
(отмена по таймеру). Строгий разбор JSON и проверка `schema` = `DATA_SCHEMA` (на переходе
контракта — П§8; значение обязано равняться `meta.schema` книги — тест эксплуатации); ответ с
`Last-Modified` = `meta.published_at`, сильным `ETag` `"<sha12>.<секунды>"`,
`Cache-Control: max-age=60`, заголовком `x-data-source` (`pages` / `raw` / `edge-cache`); 304
на `If-None-Match`; 503 `not published yet` — оба источника ответили 404 (так дверь отвечает до
первой публикации); 503 `upstream unavailable` — прочие отказы без копии края; 405 на методы
кроме GET и HEAD. `/api/model` без User-Agent (или с пустым) отвечает 403 `user-agent required` —
правило держит сама функция, сборщики и сторож шлют свой UA. Поведение —
`tests/web/web_functions_check.mjs` (Node, подменённые `fetch`, `caches` и часы).

  числа; ни имени метода, сервиса или поля API, ни слова «API», ни пометки «без токена»). Правила
  панели: на шести экранах формы панели нет слов общей формы из таблицы §2 («обеих категорий»,
  «сквозь цикл», купон бессрочных инструментов, годовое собрание как срок дивиденда), нет рабочих

  расходов к доходам рядом с термином книги) и нет дисклеймеров. Вторая часть скрипта читает

## 8. Выкладка

`npx wrangler@4.135.0 pages deploy web --project-name tzi-850-t --branch main` из корня рабочей
копии на коммите `main` (функции wrangler берёт из `functions/`). **Проект Pages `tzi-850-t`
создаётся один раз владельцем** — в панели Cloudflare или через API, с производственной веткой
`main`: команда выкладки проект не создаёт, а `wrangler 4.135 pages project create` создаёт
Worker, а не проект Pages. Перед первой выкладкой проекта ещё нет: шаг его создания и проверка
`npx wrangler@4.135.0 pages project list` (в списке должен появиться `tzi-850-t`) — в
`ops/README.md`, раздел «Установка на сервер», вместе с приёмкой двери. ID аккаунта и токен
Cloudflare в репозиторий не пишутся. Метка `--branch` обязана совпадать с производственной веткой,
иначе выкладка молча уйдёт в предпросмотр.

Что должно существовать к первой выкладке — и создаётся владельцем, а не выкладкой:

| Что | Имя | Зачем |
|---|---|---|
| публичный репозиторий кода | `temp-zero-inode-850-t` | клон `main` на сервере, CI |
| публичный репозиторий данных с веткой `release` и включённым GitHub Pages | `temp-zero-inode-850-t-data` | выпуски: `latest.json`, `releases/`, `history.json`, `journal.json`; из него читает дверь |
| проект Cloudflare Pages с производственной веткой `main` | `tzi-850-t` | статика `web/` и функция `/api/model` |

Пока репозиторий данных пуст, дверь отвечает 503 `not published yet`, а витрина пишет «Выпуск ещё
не опубликован» — это штатное состояние до первого выпуска. Порядок первого запуска: репозитории
→ проект Pages → выкладка витрины → проба источников и ручная сборка на сервере с замером →
первый выпуск → таймеры (`ops/README.md`). Меняется контракт — сначала данные (новый выпуск с
новыми полями), потом витрина (П§8).
