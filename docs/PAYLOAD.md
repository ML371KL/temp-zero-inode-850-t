# Выпуск: контракт `t-v1`

Выпуск — один JSON (`GET /api/model`), из которого витрина берёт все числа шести экранов.
Контракт — этот документ и `model/payload.py` (`REQUIRED_TOP_LEVEL`, `REQUIRED_FIELDS`,
`FORBIDDEN_FIELDS`, `validate`); имя схемы — ключ книги `meta.schema`
(`model.payload.schema_name`), в коде его нет. Методика чисел — `docs/MODEL.md` (ниже
«М§N»), экраны и карточки — `docs/DASHBOARD.md`. Новое число для экрана сначала появляется
здесь и в `model/payload.py`, потом во фронте. Имена ключей книги и выводимых величин — из
М, приложение A; поля фактов — М, приложение B. Путь через точку в этом документе — поле
выпуска; ключ книги или факт, из которого поле берётся, стоит в скобках после поля (префиксы
`meta`, `capital`, `dividends`, `checks` у книги и выпуска совпадают — различает контекст).

Контракт двухслойный. Обязательные поля — общий для панелей семейства каркас: 28 верхних
блоков и их узлы. Всё, чем эта панель отличается, — делитель «на акцию», квартальные дивиденды
по периодам, требование к капиталу с глиссадой и рост, на который хватает капитала, «цена
правила», числа гейтов знака и печатаемая маржа после фазы роста, путь к терминалу, мост трёх
прибылей, месячная таблица операционных результатов —
**необязательные узлы внутри тех же блоков** (помечены `?`); новых верхних блоков нет. Карточка
витрины рисуется только при наличии своего узла, выпуск без этих узлов остаётся годным. Поля
каркаса, которым у эмитента нечего нести (вторая категория акций, проверка формулы DPS до
копейки, ступень лестницы с порогом норматива, оценка квартала по РСБУ, купон бессрочных
инструментов), остаются в контракте пустыми — `null`, пустым списком или нулём; сводка — §9.

## 0. Правила

### 0.1. Фронт ничего не считает, кроме λ

* Числа — только из выпуска. **Единственный пересчёт — ползунок λ** (доверие своему взгляду
  на ставки, М§9–§10): центр прогона = низ + λ·(верх − низ) по `fair_value.headline.low_draws`
  / `high_draws`, квантиль тип 7, печать — к `fair_value.headline.print_step` половиной вверх
  (§0.3); точка = `fair_value.rates_view.low + λ·(high − low)`.
* Всё остальное, что зависит от λ, витрина берёт из **таблиц `by_lambda`** на сетке
  λ = 0; 0,05; …; 1 (`model/payload.py::LAMBDA_STEPS = 20`; шаг = `fair_value.headline.lambda_step`
  = `step` ползунка — тест `test_the_sliders_steps_are_the_lambda_grid`):
  `fair_value.headline.by_lambda` (P(ниже рынка) и потенциал по каждому тикеру, перцентиль
  рынка, среднее) и `fair_value.bank_first_line.by_lambda` (капитал на дату оценки,
  справедливый и рыночный P/B, PV избыточной доходности модели и рынка, ROE после фазы роста,
  стоимость капитала, ₽ за 1 п.п. ROE, за 0,1 п.п. CoR и ЧПМ, за 1 п.п. запаса капитала).
  λ книги вне сетки — лишняя строка; при λ книги строка равна заголовку (validate). Прочие
  экраны всегда показывают λ книги.
* **Доля прироста кредитных книг** (М§4.13; в методике тоже λ, с индексом квартала) —
  выход ядра, а не ползунок: витрина печатает её из `capital.growth` как есть и ничего по ней
  не пересчитывает.
* Разрешённая арифметика отображения: форматирование, доли → проценты, концы «значение ±
  ошибка», минимум–максимум, счётчики, сортировка, дни до даты (от `meta.valuation_date`),
  возраст выпуска (по часам зрителя). Любое другое число — поле выпуска.
* Витрина читает только объявленное: каждое `d.<блок>` — в `REQUIRED_TOP_LEVEL` (тест
  `test_frontend_reads_only_declared_blocks`), каждое `d.<блок>.<поле>` — поле этого
  документа. Поля `FORBIDDEN_FIELDS` (§6) витрина не читает, их появление роняет сборку.
* Подписи — из выпуска, не из словарей фронта: имя и тикеры — `meta.company`, миры —
  `worlds.rows.<W>.name`, режимы — `regimes.rows.<r>.title`, сценарии капитала —
  `capital.scenarios.<s>.title`, слои — `layers.<L>.title`, нормативы — `capital.titles`,
  базис прибыли и ROE — `meta.basis_labels`, делитель — `meta.shares.divisor_label`, гейты,
  флаги и инварианты — `title`. Литералов эмитента в `web/app.js` нет (тест); имя эмитента —
  только статическим текстом `index.html` и `404.html` (DASHBOARD §2).

### 0.2. Единицы и форматы

| Величина | Единица | Пример |
|---|---|---|
| деньги (капитал, прибыль, строки ОПУ и баланса, пул дивиденда) | млрд ₽ | `756.8` |
| цена, стоимость на акцию, DPS (после дробления), прогоны полосы | ₽ | `271.2` |
| акции | млн шт. | `2682.748` |
| ставки, доли, CoR, ЧПМ, ROE, C/I, нормативы, вероятности, массы | доля единицы | `0.0125` = 1,25 % |
| разности долей (сдвиги, запасы, «п.п.» в имени поля) | доля единицы | `0.003` = 0,3 п.п. |
| поля `*_bp` | базисные пункты числом | `35` |
| мультипликаторы (P/B, P/E) | разы | `0.9612` |

* **Периоды:** квартал `2026Q3`, месяц `2026M09`, год — целое `2027`; полугодие `2026H2` —
  только в происхождении миров. Подпись периода — функция витрины `periodLabel`
  («3 кв. 2026», «сентябрь 2026»).
* **Даты** — `YYYY-MM-DD` (календарный день по Москве); **моменты** — ISO UTC с секундами
  (`2026-09-30T16:05:12+00:00`); время сделки — `HH:MM` МСК.
* **Базис.** У каждого блока и подблока с отчётными числами — поле `basis`: `ifrs` (МСФО
  группы), `ras` (РСБУ банка: формы ЦБ и прибыль банка из месячного релиза), `mgmt`
  (управленческие данные эмитента: упр. ЧПМ, CoR, C/I и ROE, гайденс, ряды месячного релиза
  «Операционные результаты»), `engine` (МСФО-базис движка после моста, М§4.6), `regulatory`
  (нормативы ЦБ: Н20.x банковской группы, Н1.x банка — в том числе нормативы банка из форм ЦБ,
  хотя сама отчётность — РСБУ), `sector` (прогноз по банковскому сектору, а не отчётность
  эмитента), `market` (рыночные данные: цены, кривая, ставки рынка и ЦБ). Других кодов нет
  (`model/payload.py::BASIS_CODES`): код без подписи в словаре витрины не вводится. В одном поле
  базисы не смешиваются. Упр. ЧПМ, CoR и C/I выпуска переводит мостом сборка (поля `*_mgmt`),
  фронт мост не применяет.
* **Какая прибыль.** Прибыль выпуска — операционная прибыль акционеров (определение эмитента:
  без переоценки пакета Яндекса и процентов по долгу под него; на ней стоят строки движка в
  фактах, М§1). От неё считаются ROE, P/E, база дивиденда, нау-каст и гайденс. Какая прибыль
  и какой капитал стоят в отношении, говорит подпись выпуска: `meta.basis_labels` (`profit`,
  `roe`, `divisor`) печатается у каждого ROE и P/E; ROE по определению эмитента (к операционному
  капиталу) — отдельным полем `history.ltm.roe_issuer` со своей подписью; отчётная прибыль —
  рядом, мостом `history.three_profits`. Поля прибыли с базисом `ifrs` несут операционную
  прибыль: строки МСФО, приведённые к определению эмитента.
* **Нераскрытое и непосчитанное — `null` при присутствующем поле** (не 0 и не пропуск).
  Пропавшее поле — отказ сборки, кроме помеченных `?` (необязательные: могут отсутствовать
  или быть `null`, витрина пишет причину).
* **Коды единиц строк** (поле `unit` строк `judgements`, `reverse_dcf`, `book`, `inputs`,
  `nowcast.targets`, `checks.control_model` и плиток `indicators.tiles`; словарь витрины,
  `model/payload.py::UNIT_CODES`; validate сверяет каждое такое поле со словарём): `pct` и `share` — доля
  (печать в %), `pp` — сдвиг доли (п.п.), `bp` — базисные пункты, `bn` — млрд ₽, `rub` и `price`
  — ₽, `number` — число, `years` — годы, `level` — уровень без единицы, `mix` — доля смеси
  (0…1), `dict` — словарь долей, `count` — штуки, `version` — строка как есть (версия, хэш),
  `date` — дата `YYYY-MM-DD`, `period` — период (`2026Q2`; печатается подписью периода). Слова
  книги («доля», «п.п.», «млрд ₽»…) сборка переводит в коды; витрина слов единиц не разбирает.
  Единицу оси суждения задаёт поле `unit` оси книги, без него — пути оси (М§10): сдвиг доли —
  `pp`, срок — `years`, коэффициент — `number`; по величине значения единица не угадывается.
* **Служебного текста на экране нет:** строки выпуска, которые витрина печатает (`title`,
  `name`, `note`, `message`, `detail`, `source`, `src`, `equation`, `explanation`), — словами для
  владельца: без имён полей и ключей (`loan_growth.corporate`), без `true`/`false`, `inf`,
  кортежей и e-нотации (малое число — как допуск: «1·10⁻⁹»), без меток класса допущения («[В]»,
  «[Ф]» — словом: «оценка», «факт»), без путей к листам и файлам, без рабочих пометок («вопрос
  ведущему», «первичку собрать», «без токена»), без имён методов и полей API источника (источник
  называется так, как его назвал бы владелец: «решения собраний акционеров», «брокерский
  календарь дивидендов»); хвост `sha256` — только в карточке «Выпуск и книга». Числительные
  согласованы с числом: дробное число — «1,6 года» (не «лет»), счётчики — «1 проверка», «3 проверки»,
  «5 проверок». Доли — в
  процентах, разности долей (спреды к опоре, сдвиги, запасы) — в п.п.; периоды — словами («за
  сентябрь 2026»), не кодом `2026M09`; даты — с годом («30.09.2026»), версии — с именем
  («book-1.0»): короткая дата и голый номер версии читаются как дробь. Правится источник строки
  (книга, факты, ядро), а не маска на витрине; запреты держит общий тест текста экранов.

### 0.3. Округление

Выпуск хранит точные значения с ограниченной точностью (`model/payload.py::PRECISION`):

| Что | Точность |
|---|---|
| цены и стоимости на акцию | 0,01 ₽ |
| прогоны `low_draws` / `high_draws` | 0,1 ₽ (М§10); статистики заголовка и строк `by_lambda` считаются по округлённым прогонам — так же, как их пересчитает фронт |
| печатаемые (`printed_*`) | кратно `print_step`: `ROUND_HALF_UP(точное / шаг) × шаг` в десятичной арифметике; фронт — `roundHalfUp` |
| деньги | 0,01 млрд ₽; годовые массивы клеток (`grid.cells[].annual`) — 0,1 |
| доли | 1e-6; массивы клеток — 1e-4 (0,01 п.п.) |
| вероятности и массы | 1e-6 |
| мультипликаторы | 1e-4 |
| DPS | прогноз — 1e-4 ₽ (модель его не округляет, М§5.1), в массивах клеток — 0,01; объявленный — как объявлен, на акцию после дробления (значение решения до дробления — отдельным полем `dps_pre_split`) |
| акции | 0,001 млн шт. |
| прочее | 9 значащих цифр |

Суммы вероятностей и тождества validate сверяет на хранимых числах с допуском их точности
(вероятности — 1e-5, деньги — 0,05 млрд ₽). Точные тождества держит ядро (М§14.1).

### 0.4. Хэш, размер, публикация

* **Хэш** `meta.payload_sha256` — sha256 канонического JSON (`sort_keys`, `ensure_ascii=False`,
  разделители `,` и `:`, UTF-8) **без** `meta.generated_at`, `meta.published_at`,
  `meta.payload_sha256`, `meta.previous_sha256`, `meta.bytes`, `live.fetched_at`,
  `nowcast.journal.releases`, `nowcast.journal.entries[].release_sha` и блоков `changes` и
  `valuation_history`. Время сборки и ссылки на прошлые выпуски — вне содержания: иначе каждая
  пересборка на тех же входах давала бы новый выпуск (блок, ссылающийся на прошлый выпуск,
  внутри хэша превращает три сборки подряд в три выпуска). `changes` и `valuation_history`
  заполняются после подсчёта хэша.
* **Размер** `meta.bytes` — байты компактного JSON (разделители `,` и `:`, UTF-8) выпуска без
  `meta.published_at` и без самого `meta.bytes` (замер — до записи поля). Потолок — **500 000**
  (М§14.1): больший выпуск не публикуется;
  сборка предупреждает с 400 000. Файлы ветки данных `releases/<sha256>.json` и `latest.json`
  пишутся компактно, без отступов (`docs/INTERFACES.md` §6): файл выпуска ≈ `meta.bytes`.
* **`meta.published_at`** вписывает публикация (`ops/publish.py`); из него дверь ставит
  `Last-Modified`, по нему живёт сторож `dash-watch`. Выпуск с тем же хэшем повторно не
  публикуется.
* **Быстрая сборка** (`meta.fast: true`: меньше прогонов, без поисков) не публикуется —
  отказ публикации.

### 0.5. Бюджет блоков

Потолок 500 КБ — на весь выпуск. Ориентиры по блокам — замер живого выпуска книги с верхними
объёмами там, где история ещё не накоплена (36 клеток, 2 × 2 000 прогонов, 400 строк истории
оценки, 21 плитка по 60 точек, журнал за 4 события, перечень всех гейтов панели, из которых
сработавшие — около трети — несут объяснение целиком, сверка с контрольной моделью, кириллица —
2 байта на букву): **около 390 КБ**. Замер на собранном выпуске сервера — шаг приёмки
(DASHBOARD §7); таблица нужна, чтобы рост одного блока был виден сразу:

| Блок | Ориентир, КБ | Что весит |
|---|---|---|
| `checks` | 60 | перечень всех гейтов с сообщениями и коридорами (≈30 КБ: объяснения сработавших — целиком), сверка с контрольной моделью (около сотни строк, ≈21 КБ), числа гейтов знака и стоимости средств |
| `fair_value` | 49 | 2 × 2 000 прогонов (≈24 КБ при ценах ≈300 ₽ с шагом 0,1), две таблицы `by_lambda`, вклады осей (≈10 КБ) |
| `grid` | 42 | 36 клеток с годовыми массивами |
| `indicators` | 38 | плитки с историей ≤ 60 точек (столбцами) |
| `valuation_history` | 30 | ≤ 400 строк (столбцами), одна цена |
| `judgements` | 25 | строки осей с источником ≤ 80 знаков (полный — в книге), концы связок |
| `calendar` | 22 | события года вперёд с окнами дат |
| `nowcast` | 20 | месячная таблица за 15 месяцев (≈6 КБ), ретро, журнал за 4 последних события |
| `capital`, `dividends` | по 16 | требование с глиссадой и рост по кварталам и годам; квартальные DPS, реестр и история по периодам |
| `paths` | 15 | годовой и квартальный путь смеси, уровни после фазы роста и модальная клетка |
| `market` | 15 | история цены, аналоги |
| `worlds` | 10–12 | |
| остальные | ≤ 9 каждый | в `book` — справочные варианты (≈1 КБ) |

Сборка предупреждает с 400 000 байт. Если потолок начнёт жать — первым прореживать
`valuation_history`, затем укоротить историю плиток `indicators` до 40 точек.

## 2. Поля блоков

Все перечисленные поля обязательны (`REQUIRED_FIELDS`), **в том числе поля вложенных узлов**
(`a.b` — объект, `a.b[]` — каждый элемент списка, `a.b.<k>` — каждое значение словаря по
ключам `<W>`, `<r>`, `<s>`, `<t>`), кроме помеченных `?`. Новые поля добавлять можно (витрина их
не видит, пока не начнёт читать); пропавшее поле — отказ сборки. У необязательного узла `?`
стоит у его имени: узла может не быть, но если он есть, его поля обязательны — кроме тех, что
помечены сами.

**Запись полей** (её разбирает тест полноты `REQUIRED_FIELDS` по этому разделу): поле — имя в
обратных кавычках; поля узла — внутри `{…}` после имени узла, поля элементов списка — внутри
`[{…}]`; `?` после имени — необязательное; текст в скобках и после тире — пояснение, не поле;
значения перечислений (`live` | `fallback`) — не поля.

книги репозитория.

## 4. История оценки по выпускам (`valuation_history`)

Витрина показывает, как медиана и полосы менялись от выпуска к выпуску против цены, с
отсечками и сменами книги (экран «Допущения»).

* **Источник** — `history.json` ветки `release` репозитория данных: строку на каждую публикацию
  и откат пишет `ops/publish.py`: {`published_at`, `event` (`publish` | `rollback`),
  `payload_sha256`, `previous_sha256`, `generated_at`, `valuation_date`, `facts_date`,
  `book_version`, `engine_commit`, `prices` {<t>}, `median`, `band80`, `band50`, `point`,
  `printed_median`, `bytes`, `note?`}. Сборка (`python -m model.build_release`) читает его из
  клона репозитория данных (`BANK_DATA_REPO_DIR`, `docs/INTERFACES.md`); нет клона или
  истории — массивы блока пустые, выпуск собирается.
* **Прореживание:** день (МСК, по `published_at`) — последняя строка дня; старше 180 дней —
  последняя строка недели; старше двух лет — последняя строка месяца. Не больше 400 строк
  (`model/payload.py::HISTORY_ROWS`).
* **Поля** (столбцами — массивы одной длины): `date` (день публикации, МСК), `sha` (12 hex),
  `median`, `p10`, `p25`, `p75`, `p90`, `point`, `price` {<t>: []}; плюс `rollbacks` [индексы
  строк-откатов], `book_changes` [{`date`, `from`, `to`}] (смены версии книги — вертикали
  графика), `rule` (прореживание словами), `source` (словами). Дата оценки, версия книги и
  прочее по строке — в `history.json`, в выпуск не идут.
* **Текущий выпуск** в блок не входит (его строки ещё нет при сборке): последнюю точку витрина
  берёт из `fair_value.headline` и `market.prices`. Отсечки — `dividends.history[].ex_date` и
  `dividends.register[].ex_date`: после экс-даты оценка падает на DPS × акции в обращении /
  делитель, график это показывает; при квартальном календаре отсечек в году три-четыре.
* Блок вне хэша (§0.4): история растёт с публикациями, содержание выпуска — нет.

## 5. Что читает каждый экран

## 7. `validate`

`model/payload.py::validate(payload, *, publish=False, schema=None)` в сборке и ещё раз над
записанным файлом (`python -m model.build_release --check`); отказ — код 1, на витрине остаётся
прежний выпуск. Имя схемы — параметр `schema`, а без него — `meta.schema` книги репозитория.

1. `schema` = имени схемы книги (`"t-v1"`); все блоки `REQUIRED_TOP_LEVEL` и поля `REQUIRED_FIELDS` — с вложенными
   узлами §2 (`a.b`, `a.b[]` — каждый элемент, `a.b.<k>` — каждое значение словаря); ни одного
   поля `FORBIDDEN_FIELDS`. **Полнота договора** — тест: каждый узел и каждое поле §2 (запись — §2,
   вступление) есть в `REQUIRED_FIELDS` с той же пометкой `?`, и наоборот; пропажа поля во
   вложенном узле роняет сборку, а не карточку витрины. Необязательного узла может не быть;
   присутствующий узел проверяется по своим полям. Незнакомое поле контракт не ломает.
2. Все числа конечны (`allow_nan=False`); `meta.bytes` = измеренному и ≤ 500 000;
   `meta.payload_sha256` = хэшу содержания (§0.4); `meta.fast` = `false` для публикации.
3. **Гигиена** (выпуск публичен): ни почты, ни телефона, ни IPv4 (кроме петли и RFC 5737), ни пути
   файловой системы в строках выпуска (`HYGIENE_RULES`).
4. **Компания:** `main_ticker` ∈ `tickers`; `market.prices`, `headline.market_by_ticker`,
   `p_below_by_ticker`, `upside` — по каждому тикеру; `market.price` = цене главного.
5. **Заголовок:** медиана, полосы, среднее и P(ниже рынка) при λ книги воспроизводятся из
   `low_draws`/`high_draws` правилом §0.1 (квантили и среднее — до 0,005 ₽, P — строго);
   `printed_*` = округлению точного (§0.3); 0 ≤ P10 ≤ P25 ≤ медиана ≤ P75 ≤ P90 ≤
   `ceiling_x_market` × цена главного тикера; каждая строка `by_lambda` — тем же правилом при
   своём λ; строка при λ книги = заголовку; сетка λ — 21 шаг с шагом `lambda_step`.
6. **Точка:** `central` = `low` + λ·(`high` − `low`); = `layers.headline_mix.price` = формуле М§8.2
   на `headline_mix` (с `fair_value.bridge.pending_dividend`) на делителе выпуска —
   `meta.shares.divisor_mln`, а без поля — `meta.shares.outstanding_mln`; строки `waterfall`
   складываются в `v0` и `equity`; `rates_view.rub` = `high` − `low`.
7. **Язык банка:** `market_pb` = Cap / `bv_v` = `market.multiples.pb`; `excess_*` = V − `bv_v`; `excess_market` = Cap −
   `bv_v`; строка `bank_first_line.by_lambda` при λ книги = полям блока.
8. **Слои и сетка:** веса миров и вероятности клеток каждого слоя в сумме 1; `v0` слоя = Σ P·`v`;
   `v0 = bv_v + pv_ri_explicit + pv_terminal`; 36 клеток, по одной на каждую тройку.
9. **Мост и дивиденды:** `fair_value.bridge.amount` = Σ `rows` со знаком; записи реестра: 0 < DPS
   < 0,5 × цены, экс-дата = отсечка; `formula_check` — все строки `ok`, и строки двух лет до якоря
   обязательны — только при `dividends.policy.history_test` = `exact` или без этого поля: при
   `cap` список пуст, тест несут строки `cap_check`; `next_expected.dps` = DPS реестра при
   `status` ≠ `model` (запись сверяется по `period`, если поле есть, иначе по `year`), иначе =
   `dps_policy`.
10. **Капитал:** мост норматива сходится (`start + Σ pp = end`) и начинается с факта якоря;
    норматив смеси — в определении движка (§2 `capital`): `mix.n20` равен ожиданию нормативов
    клеток под весами смеси в допуске 0,05 п.п., а при поле `capital.mix_tolerance` — в допуске
    этого поля (больше нуля и не шире 0,5 п.п.); `by_scenario` и `scenarios` — массивы
    длины `capital.years`; `capital_gap.cells` — число, `cell_list` — список.
11. **Дерево ROE и путь:** `roa × leverage = roe` (1e-5); в каждой строке `paths.annual[]` `pbt`
    равна сумме строк года (§2 `paths`; допуск денег на строку).
12. **Вклады и суждения:** `contributions[].share` в сумме 1; `judgements.rows[].source` непуст
    и не служебный путь; `judgements.off_band_shift.rub` = Σ `mean_shift` строк с `in_band: false`.
13. **Проверки:** `checks.invariants_broken` = 0; сработавший гейт без действующего объяснения —
    нет записи, срок истёк или масса вне коридора (М§14.2) — отказ; истекающее объяснение — флаг
    `explanation_expiring`, не отказ и не тревога; защита заголовка (М§14.4) — отказ без новой
    книги, новой даты фактов или действующей записки.
14. **Форматы:** периоды разбираются (`YYYYQn`, `YYYYMmm`, годы — целые; `history.gaps[].period` —
    ещё и диапазон `YYYYQn–YYYYQn`), даты — ISO; `null` — только в полях, где он разрешён
    (нераскрытое, `?`); `unit` строк и плиток (`indicators.tiles[].unit`) и `basis` — из кодов
    §0.2; каждый `guidance.revisions[].key` есть среди `guidance.items[].key`; в
    `checks.gates[].message` нет `inf` и кортежей; событие календаря `form102` — с окном
    (`precision: window`); диапазоны `history.gaps` одного базиса не пересекаются; у события
    `meta.shares.corporate_actions[]` поле `factor`, когда оно есть, — число больше нуля.
15. **Узлы панели, когда они есть:** `meta.shares.divisor_mln` > 0; массивы `capital.requirement`
    и `capital.growth` — длины своих осей (`periods`, `years`); в `capital.rule_price.rows` ровно
    одна строка с `current: true`; каждая строка `history.three_profits` сходится: операционная
    прибыль = прибыль акционеров − эффект пакета − проценты по долгу (допуск денег); у события
    календаря с `estimated: true` есть окно (`earliest`, `latest`) и `confirmed` = `false`; строка,
    названная в `capital.requirement.compare`, есть в `capital.requirement.mix`; узлы
    `checks.volume_sign` и `checks.stress_sign` согласованы со своими гейтами: гейт сработал тогда
    и только тогда, когда узел несёт `ok: false`. Числа гейтов: узел `checks.funds_cost_to_key` согласован с гейтом так же, как узлы гейтов знака (гейт сработал тогда и только тогда, когда узел несёт `ok: false`).
    Сводка сверки с контрольной моделью: счётчики, когда сводка их несёт, отвечают её строкам —
    `n_rows` не меньше числа строк `rows`, `n_bad` не меньше числа показанных строк вне допуска и
    не больше `n_rows`, `all_ok: true` — только без строк вне допуска; `valuation_date` — дата ISO.

## 8. Изменение контракта

* **Добавить поле или блок** — можно без смены схемы: сначала выпуск (данные), потом витрина,
  которая его читает (витрина, читающая новые поля до первого такого выпуска, показала бы пустые
  карточки). Новое поле — в §2 и в `REQUIRED_FIELDS` с той же пометкой `?`; новый блок — в
  `REQUIRED_TOP_LEVEL`, здесь и в матрице §5.
* **Убрать или переименовать** — новая схема `t-v2`: дверь на время перехода принимает обе,
  витрина читает обе, старое имя уходит в `FORBIDDEN_FIELDS`. Запись — `docs/CHANGELOG.md`.
  До первой публикации выпуска контракт `t-v1` правится на месте, без смены имени схемы:
  выпусков ещё не было, читателей у него нет; снятое поле всё равно уходит в `FORBIDDEN_FIELDS`.
* **Имя схемы** живёт в книге (`meta.schema`), у двери — в её настройке `DATA_SCHEMA`, у
  публикации — в настройке `ops/publish.py`; три значения сверяет тест эксплуатации. Прошлым
  выпуском сборка считает только выпуск той же схемы.
* **Каркас и панель.** Обязательная часть контракта общая для панелей семейства: блоки и поля
  без литералов эмитента — имя, тикеры, регномер, подписи нормативов, базиса и органа решения о
  дивиденде берутся из книги. Особенности панели — только необязательными узлами внутри
  существующих блоков; у панели без таких особенностей их нет. Перенос на другого эмитента —
  `docs/PORTING.md`.

## 9. Что у эмитента пусто, а что читается иначе

Поля каркаса остаются в контракте и там, где эмитенту нечего в них нести: витрина по пустому
значению карточку или строку не рисует, validate пустое значение принимает.

| Поле | Что несёт | Почему |

| `dividends.formula_check[]` | пустой список | вид теста истории выплат — `cap`: политика задаёт потолок, а не формулу; тест несёт `dividends.cap_check[]` |
| `dividends.ladder[]` | одна строка — «Выплата по политике» | порога норматива в политике нет; ступень с порогом 0 не печатается |
| `dividends.policy.threshold`, `capital.policy_threshold`, `dividends.next_expected.condition.threshold` | 0 | то же |
| `dividends.policy.steps` | пустой список | одна ступень; в квартальном режиме ступеней нет |
| списки и словари по тикерам: `meta.company.share_classes`, `meta.shares.by_ticker`, `market.prices`, `market.cap_by_ticker`, `market.price_history`, поля вида `{<t>}`, `valuation_history.price` | одна строка, один ключ | одна категория акций |
| `dividends.history[].dps_preferred` | `null` | второй категории акций нет |
| `dividends.history[].ni_shareholders`, `.payout_ratio` | `null` | строка истории — решение за квартал; прибыль года и доля выплат — `dividends.cap_check[]` |
