# Решения: владельца и ведущего

Журнал решений, на которых стоят модель и конвейер панели «Т-Технологии 850». Числа
книги с опорами и осями — `data/assumptions/ASSUMPTIONS-BOOK.md`; методика —
`docs/MODEL.md`; контракт выпуска — `docs/PAYLOAD.md`. Решение меняется только новым
решением с датой (запись ниже, старая не стирается); книга — только новой версией.
Решения панели-образца (Сбер), на которых стоит общий код, — в её журнале
(репозиторий `ML371KL/temp-zero-inode-850-sber`, файл `docs/DECISIONS.md`); здесь из
них названы те, что действуют как решения семейства.

Обозначения: [Ф] — факт с источником, [Р] — расчёт, [В] — суждение. Доли — как в
книге (0,001 = 0,1 п.п.). Базисы: МСФО группы; РСБУ банка; банковская группа по ЦБ
(нормативы Н20.x); упр. — управленческие метрики эмитента; операционный — прибыль и
капитал акционеров в определении эмитента (без переоценки пакета Яндекса и процентов
по долгу под него); движок — базис ядра после мостов. Всё «на акцию» — после
дробления 1:10 (15.04.2026).

## Часть 1. Решения владельца (07.10.2026)

1. **Задача.** По логике, принципам и практикам модели Сбера построить модель
   справедливой стоимости акции МКПАО «Т-Технологии» (тикер T, Мосбиржа) и дашборд
   https://tzi-850-t.pages.dev — с учётом собственной экономики компании.
2. **Репозитории — публичные,** отдельные на банк: код —
   `ML371KL/temp-zero-inode-850-t` (`main`), выпуски —
   `ML371KL/temp-zero-inode-850-t-data` (ветка `release`, GitHub Pages).
3. **Новая папка.** Работа идёт в своей рабочей копии и своей папке передачи;
   репозиторий и папка панели Сбера не меняются — она на бою.
4. **Доступы и разрешения** — владелец дал все, что нужны для работы над панелью
   (сервер, токен брокерского API, репозитории, Cloudflare Pages). Значений здесь нет:
   их хранит справочник владельца вне репозитория.

### Унаследованные решения семейства

Приняты владельцем для панели Сбера (30.09–06.10.2026) и действуют здесь без
изменений.

- **ERP — 5,57 %,** конвенция семейства 850; разрыв с рынком печатается строкой «что
  в цене», а не подгоняется.
- **Репозиторий на банк.** Общность держится правилами: ни одного литерала банка в
  `model/`, `indicators/`, `web/app.js`, `functions/` (имя, тикер, регномер, даты — из
  книги и `meta.company`) и журнал переноса исправлений `docs/PORTING.md`.
- **Сервер и секреты разрешены.** Сбор, приватный сырой архив с винтажами, журнал
  прогнозов, сборка и публикация — на общем сервере панелей владельца (systemd,
  пользователь `dash`); код и выпуски — публичные репозитории; CI — GitHub Actions;
  витрина — Cloudflare Pages; тревоги и сторож свежести — общие для панелей.
- **T-Invest подключается:** токен «только чтение»; условия API запрещают публичные
  сервисы на нём — витрина для личного пользования, в выпуск идут только агрегаты,
  которые печатает витрина; ответы API в репозиторий не переносятся ни выписками, ни
  именами полей.
- **Ручной слой — Claude по просьбе владельца;** всё, что можно, автоматизируется.
- **Защиту сайтов от ботов не обходим.** У этого эмитента сайт и документы открыты —
  обходить нечего; правило действует для любого другого источника.
- **Миры ставок** — байтовая копия записи семейства и её рецепт; одна конвенция
  вероятностей; кризис — режим доходности и кредитного цикла, а не четвёртый мир.
- **Метод:** остаточный доход — печать, дивидендная модель с капитальным ограничением
  — инвариант сборки; шаг — квартал, простые проценты по дням, сложный процент —
  только в дисконте; явный горизонт до 2036К4 и терминал.
- **Витрина** — дизайн-система семейства, шесть экранов, без дисклеймеров и без
  фирменного стиля эмитента. Центры допущений несмещённые, осторожность — в
  диапазонах; сложность — только там, где окупается.

| Тема | Решение (номер решения ведущего) |
|---|---|
| Контур и базис | Книги ЧПД и ЧПМ — на базисе эмитента: проценты по долгу нефинансовых компаний, в том числе под пакет Яндекса, остаются в оптовом фондировании и в ЧПД. Строка пакета равна возврату этих процентов (поправка эмитента «проценты по займам» / 0,75), поэтому прибыль движка равна операционной прибыли эмитента — тест фактов на квартале якоря. Долг под пакет постоянен в рублях; ось — сдвиг пути. Прочие активы делятся на растущие с бизнесом и постоянные в рублях (`volumes.other_assets_fixed`, своя плотность RWA); книга ценных бумаг — только долговые бумаги; кредиты МСБ растут с сектором бизнеса, риск — розничный; знаменатель CoR движка — сумма кредитных книг, и мост CoR считается на ней же (№ 2–5) |
| Делитель | Одно число N_div для цены, капитала на акцию, капитализации, P/B, P/E и всех строк «на акцию»; клетка, мост и объявленный дивиденд считают отток на акции в обращении, скачок на экс-дату равен −DPS × N_out / N_div (№ 2) |

- **Дивиденды:** закрытый квартал прибыли без своей строки истории, покрытый строкой более позднего

  проверяемым значением идут оба её конца; корень на краю отрезка поиска печатается «недостижимо».
- **Индикаторы:** базис целей нау-каста читается из переданной книги; тревога реестра сборщиков
  считает закрытым период с записью о выплате в стартовом реестре фактов.
- **Перезаякоривание:** инструмент и режим ожидаемого отчёта сборщика фактов — под квартальные

  активы, экономически собственные акции; сухой прогон «факт = ожидание ⇒ механика ≈ 0» на ожидаемом

- **Производительность и бюджеты:** цель — полный выпуск на сервере (4 ядра) не дольше 30 минут;

### Принцип калибровки уровней

**Уровень, взятый из окна фактов, стоит в том мире, условиям которого окно отвечает.** Окно —
4-й квартал 2024 года … 2-й квартал 2026 года — прошло при ключевой ставке 14,6–21 %: это мир
«Рыночный как есть». Поэтому, если ничего не изменится — ни ставки, ни состав баланса, —
модель печатает уровни окна. В миры с другими ставками уровни переносят названные суждения о
чувствительности к ставке — передача у маржи, чувствительность стоимости риска к реальной ставке, —
каждое со своей осью. Состав баланса клетки меняет печатаемую маржу арифметикой книг: кредит вместо
ликвидных активов зарабатывает кредитный спред, и потолка на этот эффект нет. Печатаемые уровни
клеток и ожиданий — результат, а не суждение: они печатаются рядом с суждением и сверяются с окном
гейтом.
